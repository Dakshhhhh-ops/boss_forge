01 How it works

One chat message, one new boss.

Every screenshot below is from a real session on a Twitch channel with live Codex, recorded 2 Nov 2026.

01 / Chat

A viewer types an idea.

Anyone in chat sends !boss <idea> or redeems the Channel Points reward. The bot replies with a short code, and the streamer or a mod approves it with !approve. Viewer text is treated as data, never as instructions.

02 / Codex

Codex writes and tests it.

Each request opens a Codex SDK thread in a locked workspace with no network. Codex writes boss.json against a typed BossAPI, runs the local gate, and repairs its own mistakes, up to three attempts.

03 / The gate

The server proves it's fair.

Codex's own report is ignored. The server re-runs an unchangeable gate on the actual spec: a reference bot fights it five times. Bosses that are too unfair are rejected and refunded before they reach the stream.

04 / The fight

The streamer fights it.

A deterministic 60 Hz bullet-hell arena, captured in OBS, with a transparent overlay that tells chat everything. When the boss falls, chat gets a recap, and the creator gets the credit.

02 The fairness gate

Hard, but never cheap.

If a troll asks for a wall of bullets, the gate says no before it ever reaches the stream. Same seeds, same bot, same rules, every time.

    Hall of Fame

    Creators climb the board when their bosses beat the streamer.
